# Memory Dump Formats

VantaCore Engine processes a diverse array of volatile memory acquisition formats encountered in digital forensics and incident response.

## Supported Formats

### 1. ELF64 Core Dumps (`ET_CORE`)

ELF64 core dumps are generated by POSIX operating systems and network appliances when a process crashes or when forced via administrative commands.

- **Magic Bytes**: `\x7fELF` with 64-bit architecture identifier (`\x02`).
- **Use Cases**: Cisco ASA `lina` core dumps, Linux process dumps, GDB `gcore` captures.
- **Forensic Characteristics**: Contain `PT_NOTE` segments with thread status (`NT_PRSTATUS`), process information (`NT_PRPSINFO`), and MSR state (`NT_X86_MSR`).

### 2. Raw Physical DRAM Images

Unstructured binary images representing raw physical address spaces.

- **Characteristics**: Flat contiguous byte dumps acquired via hardware acquisition devices (PCIe DMA), hypervisor memory dumps (ESXi `.vmem`, QEMU `dump-guest-memory`), or Linux kernel modules (LiME, AVML).
- **Forensic Characteristics**: Requires top-level page table location (CR3 PML4 on x86_64) or translation heuristics (such as IDT table scanning).

### 3. Flat Appliance Firmware Memory

Monolithic firmware environments (such as Cisco IOS Classic) operating without an MMU virtual address translation layer.

- **Characteristics**: Physical memory mapping starting at fixed platform offsets (e.g., `0x60000000` or `0x00000000`).
- **Forensic Characteristics**: Handled via `FlatImageBackend` using direct physical offsets and mempool block header carving.
