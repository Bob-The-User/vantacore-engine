# Network Appliance Forensics

Forensic memory analysis of network appliances presents unique challenges that distinguish it from standard host memory forensics.

## Appliance Internal Architectures

### Cisco ASA (`lina`)

The Cisco Adaptive Security Appliance (ASA) operates the monolithic `lina` binary. In coredumps generated by `crashinfo` or `write core`, all firewall state resides within `lina`'s virtual memory address space:

- **Stateful Connection Table**: Tracks active TCP, UDP, and ICMP connections along with packet counters and NAT state.
- **Compiled ACL Rules**: In-memory rule trees compiled from access-list configurations.
- **VPN Sessions & SAs**: Active IPsec and SSL VPN tunnels. In cleartext memory, this includes IKEv1/IKEv2 pre-shared keys (PSKs).
- **CLI History Ring Buffer**: Linked lists of administrative commands executed prior to acquisition.

### Cisco IOS Classic

Classic Cisco IOS runs as a single cooperative multitasking OS on bare metal without MMU memory isolation.

- **Flat Physical Memory**: Virtual address translation is unnecessary; pointers represent physical RAM addresses.
- **Mempool Structure**: Allocations are prefixed with magic bytes (`0xAB1234CD`) allowing structural memory pool analysis.
- **RIB Routing Base**: Routing information bases and static route tables can be recovered directly from physical memory.

### Cisco IOS-XE

Cisco IOS-XE runs the IOS daemon (`IOSd`) on top of a hardened Linux kernel.

- **Dual-Layer Architecture**: Linux kernel extractors recover system processes and network interfaces, while Cisco-specific extractors recover IOSd routing and configuration state.
